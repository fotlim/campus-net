# 校园网自动登录(托盘 + 开机自启 + 多账号 + WiFi + 校时 + 网速 + 一键诊断 + 通知中心 + 唤醒重认证 + 自动修复 + 桌宠)

![version](https://img.shields.io/badge/version-1.2.8-blue)

**校园网自动认证登录 / WiFi 自动认证登录** —— Windows 装一次,之后开机自动连校园无线网、自动完成 Portal 认证、掉线自动重连。宿舍 WiFi(ChinaNet / CMCC-EDU / 沃 WiFi)、教学楼认证页都适用。

针对你学校这套 **中国电信 Dr.COM 校园网认证门户**(`http://1.1.1.4`);同一套脚本也内置了**广东电信天翼校园网**(`enet.10000.gd.cn`)和通用表单门户,换个学校不用改代码,详见 [通用版:换所学校也能用](#通用版换所学校也能用)。

设置一次,之后开机自动在后台跑,右下角有「网」图标,掉线自动重连,系统时间偏了会自动校准。

## 最快上手

1. **双击 `connect.bat`** → 弹菜单(**会自动用 Windows Terminal 打开**,所以背景图才生效)
2. **第一次运行会自动进「新手向导」**:问一句「这个 WiFi 是校园网吗」→ 不是就换名字 → 顺便填账号 → 自动认门户并生成配置
3. 想再跑一次向导:菜单里按 **`G`**(或 `-Mode wizard`)
4. 最后选 **`9`** 安装开机自启(向导最后也会问)

之后每次登录 Windows,右下角出现「网」图标就说明它在工作了。

### 向导到底做了什么

| 步骤 | 说明 |
| --- | --- |
| ① 问 WiFi | 当前连的 WiFi 是不是要认证的那个?不是就让你填名字,同时写好「目标 WiFi + 自动连接」 |
| ② 问账号 | 一个账号都没有时,顺便填(DPAPI 加密保存) |
| ③ 认门户 | 复刻"浏览器弹认证页":HTTP 302 → 网关 → HTTPS 劫持页,三路都试 |
| ④ 出配置 | 命中内置预设直接套用;没命中就**抓门户页,从表单现场生成配置**(见下) |
| ⑤ 收尾 | 可选试登录一次、可选装开机自启 |

**没命中时是怎么现场生成的**:抓门户 HTML → 找含 `password` 的 `<form>` → 抠出 `action` 当登录接口、`method` 当提交方式、账号/密码字段名,把隐藏字段(如 `wlanuserip`、`service`)原样带上,拼成

```
wlanuserip=10.1.2.3&service=internet&username={user}&password={pwd}
```

再按页面里有没有 `md5(` / `rc4` / `base64` 猜加密方式。生成结果存成 `id=custom`,成功判定留空(以真实连通性为准)。实测:用这套自动生成的配置去登录一个"隐藏字段 + md5 密码"的假门户,一次通过。

## 功能详解(① ~ ⑭)

### ① 托盘图标

右下角一个圆形「网」图标,颜色就是状态:

| 颜色 | 含义 |
| --- | --- |
| 🟢 绿 | 在线 |
| 🟠 橙 | 正在登录中 |
| 🔴 红 | 离线(会自动重连) |
| ⚪ 灰 | 守护未运行 / 状态过期 / 未设置账号 |

右键菜单:**状态 / 账号**(只读) · WiFi 自动连接开关 · 立即登录 · 切换到下一个账号 · 校正系统时间 · 连接 WiFi · 查看日志 · 一键诊断 · 打开设置菜单 · 退出托盘(同时停止守护)。

两个顺手的操作:

- **双击托盘 = 立即登录**(不用翻右键菜单)
- **气泡提示**:登录成功 / 掉线 / 恢复时右下角弹气泡,不用去翻日志

托盘同时**看管守护进程**:发现守护没在跑,它会自动拉起来;你退出托盘时守护一起停。

### ② 自动校正系统时间

为什么要做这个:门户的登录参数里有个 `auth_tag`,就是**当前毫秒时间戳**;服务器一般会校验时间窗口。**电脑时间偏得多(比如主板电池没电、虚拟机休眠后),登录就会被拒**,而且报错只会说"用户名或密码错误",非常难查。

做法:门户在**未认证时也能访问**,脚本读它响应头里的 `Date` 得到服务器时间,再和本机对比。

- 偏差 ≤ 1 秒:记一条"正常"
- 偏差大且**有管理员权限**:直接 `Set-Date` 校正
- 偏差大但**没有管理员权限**:先试 `w32tm /resync`(校园网常屏蔽 NTP),不行就**打一条醒目的警告**告诉你去开"自动设置时间"

守护模式启动时会校一次,之后**每 30 分钟**复核一次;菜单 `7` / `-Mode synctime` 可以随时手动校。

> 想让任务也能自动改时间:用**管理员**运行一次 `-Mode install -Elevated`。否则任务只有普通权限,时间偏了只会提醒不会改。

### ③ 多账号保存与切换

`accounts.json` 里可以存多个账号,每个带备注(主号 / 备用…),任何时候有一个"当前账号"。

- 菜单 `1` 添加(同名账号 = 更新密码)、`2` 切换、`3` 删除、`4` 列表
- 托盘右键「切换到下一个账号」:切换后会自动**重启守护**让它用新账号连
- 每个密码都是独立 DPAPI 加密的

### ④ 自动连接指定 WiFi

默认目标是 **`CIT-Chinanet`**,**程序一启动就以最高优先级先连它**,连上之后才做门户登录、校时等其它事。守护每轮发现掉线时也会重新确认 WiFi,不是目标网络就自动 `netsh wlan connect` 连上去。

「是否自动连接」是一个**可保存的开关**(存在 `settings.json`),三个地方都能改:

| 位置 | 说明 |
| --- | --- |
| 菜单第 `1` 项 | 放在最上面,优先级最高;点一下就切换 开/关 |
| 托盘右键第一项 | 同样一眼可见 |
| 命令行 `-NoWifi` | 本次强制不碰 WiFi(不改变设置) |

关掉之后,**启动时就不会去连 WiFi**,但门户登录照旧。

三个前提(缺一个就连不上,脚本会在日志里说清楚):

1. **Windows 里必须先存过这个 SSID 的配置** —— 手动连过一次就行。没有配置时脚本会明确报"请先手动连接一次"。
2. `CIT-Chinanet` 是 **Open(无密码)** 网络,所以不需要密码、也不需要管理员权限,一条 `netsh` 就够。
3. 无线服务 `WlanSvc` 必须在跑(停了脚本会尝试拉起,但拉起需要管理员)。

每次启动都会打一行 WiFi 状态,方便排查:

```
[INFO] WiFi 当前: CIT-Chinanet ,目标: CIT-Chinanet
```

换目标网络:菜单第 `2` 项,或 `-WifiSsid "另一个SSID"`(会写进设置,之后一律以设置为准)。

### ⑤ 一键诊断(`-Mode doctor`)

把"为什么不工作"变成"报告里第几项不正常"。11 项依次检查:无线网卡与 SSID、IP/网关、门户可达、DNS、系统时间偏差、凭据能否解密、**认证状态(含劫持判定)**、计划任务(还会核对**是否指向本目录**)、托盘与守护进程、设置、日志里的 ERROR。

```
===== 校园网自动认证 · 诊断报告 =====
 1. [OK] 无线网卡  已连接 CIT-Chinanet
 2. [OK] IP / 网关  10.8.49.25 / 10.8.48.1
 ...
 7. [OK] 认证状态  已通过认证 — 微软探测通过
11. [OK] 日志  最近 200 行没有 ERROR

汇总: 11 项正常,0 项需注意,0 项异常
报告已保存: D:\campus-net\doctor-report.txt
```

退出码:全部正常 `0`,有异常 `1`。报告会存成 `doctor-report.txt`,托盘点「一键诊断」还会自动用记事本打开 —— 要问人时直接把这份发出去。

### ⑥ 劫持检测(能认出"连着 WiFi 但没认证")

校园网最常见的情况不是"没网",而是 **HTTP 被重定向到门户** 甚至 **透明劫持返回 200**。以前只能判"不通",现在会看**内容和重定向目标**:

- 微软探测要求正文就是 `Microsoft Connect Test`
- 备选探测要求 `204` 或空响应;返回 200 带内容 = 透明劫持
- 重定向目标命中 `ac_portal` / `1.1.1.4` → 判定"未认证"

日志会写明原因,而不是笼统的"掉线":

```
[WARN] 检测到未认证/被劫持(被重定向到门户: http://1.1.1.4/ac_portal/proxy.html?...),开始重连…
```

### ⑦ 门户改版自检(全自动,无需操作)

这套脚本最脆弱的地方就是**逆向出来的接口** —— 学校一升级门户,登录就会莫名其妙失败。所以自检做成了**后台自动任务,不占菜单项、也没有开关**,平时你完全不用管。

守护每 **24 小时**自动跑一次(零副作用,只抓页面和脚本,不发登录请求),结果写进日志和 `portal-check.txt`:

```
===== 门户改版自检 =====
 1. [OK] 门户页可访问  HTTP 200,页面 91705 字符,最终地址在门户内
 2. [OK] 前端脚本  已抓取 193938 字符
 3. [OK] 登录接口 login.php  存在
 4. [OK] 密码登录参数 pwdLogin  存在
 5. [OK] RC4 加密 do_encrypt_rc4  存在
 6. [OK] 时间戳参数 auth_tag  存在

结论: 指纹全部匹配,门户未改版
```

- **通过时**:日志一行 `门户自检通过: 登录接口 / 参数 / RC4 / auth_tag 四处指纹都在`
- **发现问题时**:日志 `[WARN] 门户自检: 检测到 N 处变化,门户可能改版`,报告里写明"需要重新逆向"
- **手动触发(仅命令行,调试用)**:`-Mode check`;想连接口一起验:`-Mode check -Deep`(会发一次假账号请求)

> 反向测试过:故意把模板 ID 改成不存在的值,它准确报 `HTTP 404,页面打不开` 并判定"检测到 1 处变化"。

### ⑧ 修改窗口背景图(Windows Terminal)

菜单 `B` 可以直接给菜单窗口换背景图。**注意:这个功能依赖 Windows Terminal** —— 老式控制台(conhost)本身不支持图片背景,脚本会检测并告诉你。

操作:选 `B` → **把图片直接拖进窗口**(路径会自动带引号,脚本会去掉)→ 回车。想恢复就输入 `clear`。

细节:

- 改的是 **Windows Terminal 默认 profile**(双击 `connect.bat` 打开的就是它)的 `backgroundImage`,附带 `backgroundImageOpacity`(默认 0.35)和 `backgroundImageStretchMode=uniformToFill`
- 改之前**自动备份**成 `settings.json.bak-<时间戳>`,写回前还会校验新内容是不是合法 JSON
- 写文件用的是**无 BOM 的 UTF-8** —— 带 BOM 会让 Windows Terminal 读不懂配置
- 支持 png / jpg / bmp / gif
- 改完要**新开一个标签页或窗口**才生效(已开着的窗口不会变)

命令行等价写法:

```powershell
.\Connect-CampusNet.ps1 -Mode background -BackgroundImage "D:\图片\bg.jpg"
.\Connect-CampusNet.ps1 -Mode background -BackgroundImage "D:\图片\bg.jpg" -BackgroundOpacity 0.2
.\Connect-CampusNet.ps1 -Mode background -ClearBackground
```

### ⑨ 网速监控(常驻,没有开关)

托盘右键菜单、悬停提示、菜单顶部都能看到实时下行 / 上行速度,外加峰值和本次累计。

```
网速: ↓ 327 KB/s   ↑ 1 KB/s          ← 托盘右键菜单
峰值 ↓ 2.10 MB/s  ↑ 340 KB/s   累计 ↓1.2 GB  ↑3 MB
校园网:在线  ↓327K ↑1K               ← 鼠标悬停提示(只在线时带速度)
```

- 读数来源:直接读 .NET 的网卡字节计数(`NetworkInterface.GetIPv4Statistics()`),**不起进程、不查 WMI**,2 秒一次,长期挂着也不费资源
- 第一次只打基线(显示 `—`),第二次开始才有速度值 —— 故意的,不拿"开机以来的平均值"糊弄人
- 网卡重连导致计数归零时,负增量按 0 处理,不会算出天文数字
- 离线时不显示速度(免得看起来像在跑流量)

### ⑩ WiFi 列表自动刷新(常驻,没有开关)

Windows 的 WiFi 列表是**缓存**的:刚开机、刚唤醒、刚从别的网络切回来时,列表经常还是空的 / 过期的 —— 结果就是"明明有信号,却报没有配置 / 连不上"。所以每次连接前都会自动刷新一遍,不需要你操作,也没有开关。

具体会自动做这几件事:

1. **连接前强制刷新**:先跑 `netsh wlan show networks`(让无线服务重新扫描),再读 `profiles` / `interfaces`,三份数据一起判断
2. **列表变化写日志**:目标 SSID 消失 / 重新可见时记一行,事后好排错
3. **超时自动重试一轮**:第一次连接超时后再刷新一次列表,如果这时能看到目标(刚开机扫描慢的典型情况)就再试一次,看不到就不白等
4. **开放网络缺配置自动补**:目标 SSID 可见、是开放网络、但 Windows 里没有它的配置时,用 `netsh wlan add profile` **自动补一份**再连(仅开放网络;带密码的网络不猜)
5. **连不上时告诉你搜到了什么**:日志里列出当前可见的 SSID,不用再开别的工具看

菜单顶部显示可见网络数量;诊断报告第 12 项会报目标 SSID 是否可见、信号多少、Windows 里有没有配置。

### ⑪ 通知中心(替代会消失的气泡)

以前用的是托盘气泡(`ShowBalloonTip`)—— Win10/11 上它经常被系统吞掉,而且**留不在通知中心里**,错过就没了。现在改成 WinRT 的 Toast:

- **进通知中心**:断了/恢复了,按 `Win+N` 还能翻回来看
- **点了能干活**:通知自带按钮「打开菜单」「立即登录」「查看日志」,点一下直接执行(走 `campusnet:` 协议)
- **设置里能单独关**:设置 > 通知 里会出现一条「校园网自动登录」,不想看就关掉它,不影响登录
- **不刷屏**:同类通知有去重(比如掉线 20 秒内只发一条);守护连续 3 次登录失败才会提醒一次"可能改密码了"

自检:`-Mode notify` 会发一条测试通知,并打印通知身份、快捷方式路径、通知中心里的历史条数。托盘右键也有「发送测试通知」。

第一次运行会自动建一个开始菜单快捷方式「校园网自动登录」,这是让系统认识本应用的**必要条件**(AppUserModelID)。删掉它通知就会退回气泡。

### ⑫ 休眠 / 唤醒自动重认证

合盖睡一晚再打开,以前要等守护下一轮(最多 30 秒)才会重连。现在两条路一起走:

1. **托盘挂 `PowerModeChanged`**:一唤醒立刻起一个隐藏进程补一次认证(抢在守护前面)
2. **守护看"睡过头"**:每轮记录睡觉时长,远超检测间隔就说明刚从休眠回来,马上重新认证

重认证不是无脑重发密码:先测连通性 → 通了就什么都不做 → 不通才连 WiFi、再登录。刚唤醒网卡可能还没起来,所以最多试 3 轮、每轮隔 3 秒。成功了发通知「唤醒后已自动重新认证」,失败发「唤醒后连不上,已开始自动修复」。

### ⑬ 自动修复(DNS / Cookie / 网卡)

诊断发现**常见毛病**时不再只告诉你"哪里不对",而是先动手试一遍。修的顺序是从轻到重:

| 步骤 | 做什么 | 什么时候做 |
| --- | --- | --- |
| 1 | `ipconfig /flushdns` 清 DNS 缓存 | 总是 |
| 2 | 删掉 `cookies.txt`(门户 Cookie 残留会导致登录被判重放) | 总是 |
| 3 | 重新刷新 WiFi 列表并按配置重连 | 自动连 WiFi 开着时 |
| 4 | 与门户对时(`Set-Date`,偏差大才动手) | 总是 |
| 5 | **重置网卡**(`Restart-NetAdapter`,断网十几秒) | 只有"连续失败"或手动修复时 |

每步做完就测一次连通性,通了立刻停手——不会把能用的网络再折腾断。

触发的三个地方:

- **诊断**:发现「无线网卡 / 门户可达 / DNS 解析 / 认证状态」异常时自动跑 1~4,报告里多一行「14. 自动修复 → 已尝试… → 现在已在线」。想只看不动手,加 `-NoRepair`
- **守护**:连续失败 2 次做轻量修复,4 次才把网卡也重置(重置网卡 30 分钟内只做一次)
- **手动**:菜单 `R)` 或 `-Mode repair`,直接做全套

第 5 步要管理员权限。守护任务默认是普通权限,所以安装时会额外注册一个**提权助手任务** `CampusNet-Repair`(平时不跑,只有需要重置网卡时才被唤起,不弹 UAC)。安装时不是管理员的话这个助手任务不会注册,自动修复就跳过重置网卡、只做前 4 步。

**为什么不是直接把 dsh-pet 塞进来(运存对比)**

原版是在 Electron/WebGL 里直接播 webm,一个宠物就要 100MB 上下。这里的做法是把重活放到构建期:

| | 原版(dsh-pet / Electron) | 本项目 |
| --- | --- | --- |
| 运行时 | 独立 Electron 进程 + GPU 进程 | **复用已有的托盘进程,不新增进程** |
| 视频解码 | 每帧实时解 VP9 | **不需要**,只有 PNG 帧 |
| 常驻内存 | 100 MB 量级 | **实测 +17.6 MB**(100% 大小,见下;80% 约 +11 MB) |
| 素材体积 | 13 段 webm + 27 张图(运行时解) | 468 帧 PNG + 27 张图 ≈ 47 MB(原始分辨率,离线解好的) |

具体省下来的点:

1. **不额外起进程** —— 画在托盘进程里,内核句柄一个没多
2. **不做视频解码** —— webm 在构建时就被抠图、裁切、缩放到 PNG 帧,运行时只读文件
3. **每帧一个常驻 HBITMAP** —— 播放时只 `SelectObject` + `UpdateLayeredWindow`,不再每帧分配/释放位图
4. **懒加载 + 上限三个动作** —— 平时只驻留 idle 的 60 帧
5. **24 fps + 1ms 定时器精度**,顺手退掉了 Win11 对后台进程的电源节流
6. **黑边重做**:抠图时先把不透明像素的颜色向外扩一圈,再做边缘羽化 —— 之前那圈黑边就是"边缘像素颜色还混着黑底"造成的

## 通用版:换所学校也能用

原来的认证逻辑是写死 Dr.COM 的(1.1.1.4 + `/ac_portal/login.php` + RC4)。现在把这部分抽成了**配置驱动的认证引擎**,门户差异都放进 `portal.json`:

```json
{
  "id": "drcom",
  "name": "中国电信 Dr.COM(RC4 + auth_tag)",
  "host": "1.1.1.4",
  "page": "/ac_portal/20250303113805/pc.html?...",
  "loginUrl": "http://{host}/ac_portal/login.php",
  "method": "POST",
  "contentType": "application/x-www-form-urlencoded",
  "encrypt": "rc4_ms",
  "template": "opr=pwdLogin&userName={user}&pwd={pwd}&auth_tag={tag}&rememberPwd=0",
  "successMatch": "\"success\"\\s*:\\s*true",
  "msgMatch": "\"msg\"\\s*:\\s*\"([^\"]*)\""
}
```

**模板占位符**:`{user}` 账号、`{pwd}` 加密后的密码、`{plain}` 明文密码、`{tag}` 毫秒时间戳、`{host}` 主机。

**加密方式** `encrypt`:

| 值 | 算法 | 典型场景 |
| --- | --- | --- |
| `none` | 明文 | 自建门户、很多开源认证页 |
| `rc4_ms` | RC4,密钥 = 毫秒时间戳 | 中国电信 Dr.COM(本机现用) |
| `md5` | MD5 小写 hex | 深澜/锐捷的常见变体 |
| `sha1` | SHA1 小写 hex | 少数自建门户 |
| `base64` | Base64 | 个别老门户 |

**成功判定**:`successMatch` 是正则,命中算成功;留空则**以真实连通性为准**(`Test-Online`),适合返回体不标准的门户。`msgMatch` 用来取错误信息。

**怎么用**

```powershell
.\Connect-CampusNet.ps1 -Mode portal                  # 看当前配置 + 内置预设
.\Connect-CampusNet.ps1 -Mode portal -DetectPortal    # 抓门户页猜是哪家
.\Connect-CampusNet.ps1 -Mode portal -PortalId form   # 切到"通用表单"预设
```

菜单里也有 `O) 门户类型 / 通用认证配置`。切换后直接 `-Mode login` 就能用新配置。

**内置预设**

| id | 门户 | 状态 |
| --- | --- | --- |
| `drcom` | 中国电信 Dr.COM(RC4 + auth_tag) | ✅ 真实门户实测 |
| `esurfing` | 广东电信 天翼校园网(`enet.10000.gd.cn` 客户端协议) | ✅ 假服务器验证 |
| `form` | 通用表单(明文 / md5 / sha1 / base64) | ✅ 假服务器验证 |
| `jsonform` | 通用 JSON 表单(可带 token 两步) | ✅ 假服务器验证 |
| `srun2` | 深澜 Srun v2(token 两步 + hmd5) | 🔧 骨架(token 那步已验证) |
| `srun` | 深澜 Srun(老式单次表单) | 🔧 骨架 |
| `ruijie` | 锐捷 ePortal | 🔧 骨架 |

> ✅ = 三条链路真的跑通过;🔧 = 请求形状对、字段留好,但**密码算法/参数名各校不同**,得按抓包改两三个字段。

**引擎能力**(换学校基本就这四件事)

| 能力 | 怎么配 |
| --- | --- |
| 一次表单 POST / GET | `loginUrl` + `method` + `template` + `encrypt` |
| 先取 token 再登录 | `tokenUrl` + `tokenMethod` + `tokenRegex`,登录模板里用 `{token}` |
| JSON 体 | `contentType` 里带 `json` 即可,模板直接写 `{"username":"{user}"}`,值自动做 JSON 转义 |
| 自定义头 / Referer | `headers`(多条用 `;;` 隔开)、`referer` |

占位符:`{user}` `{pwd}`(加密后)`{plain}` `{tag}`(毫秒时间戳)`{host}` `{token}` `{clientip}`。

### 自动识别门户(就靠"连上就弹认证页"那一下)

连上校园网后浏览器会自动弹认证页,本质是**你的外网请求被 302 到了门户**。脚本直接复刻这个动作:

```
GET http://www.msftconnecttest.com/connecttest.txt   → 302  Location: <门户地址>
```

拿到 `Location` 之后看地址就能认出是哪家:

| 门户地址里出现 | 判定 | 处理 |
| --- | --- | --- |
| `ac_portal` / `1.1.1.4` / `drcom` | 中国电信 Dr.COM | 切 `drcom`,顺便把新的 `page`(模板 ID)写进配置 |
| `enet.10000.gd.cn` / `:10001` | 广东电信 天翼校园网 | 切 `esurfing` |
| `srun` / `get_challenge` | 深澜 Srun | 只提示(骨架),要手工适配 |
| `eportal` / `锐捷` / `wlan_user_ip` | 锐捷 ePortal | 只提示(骨架) |
| `sangfor` / `h3c` / `huawei` | 深信服 / H3C / 华为 | 只报厂商 |

自动切换只对**实测过**的 `drcom` / `esurfing` / `form` 生效;骨架预设不替你瞎改,只提示。

三个触发点:

```powershell
.\Connect-CampusNet.ps1 -Mode portal -AutoPortal      # 手动识别一次并写回 portal.json
.\Connect-CampusNet.ps1 -Mode portal -DetectPortal    # 只看不改(顺带打印现场参数)
# 菜单 O) 里输入 auto
```

另外**登录失败会自动试一次**:密码没错却登不上,脚本会去抓门户地址,发现门户变了(换校区、门户改版、模板 ID 变了)就自动换配置再重试一次,并把改动写进日志。

> 说明:这套自动识别解决的是"**门户地址 / 厂商 / 页面路径**"。真正发登录请求还得知道对方的参数格式和密码算法 —— 已知的那几家(Dr.COM、天翼、通用表单)内置好了;遇到没见过的厂商,`-DetectPortal` 会把地址和现场参数打出来,照着填 `portal.json` 即可。

**WiFi 名字不影响识别。** 脚本不靠 SSID 判断厂商 —— 同一所学校换名字(`young`、`wo`、`CIT-Chinanet`、`GDGM-S`……)、或者一个宿舍区两个 SSID 都很常见。SSID 只是一串要连的名字,填在菜单 `2) 设置目标 WiFi` 里(或 `-WifiSsid 'wo'`);真正的判断依据永远是**连上之后被 302 到哪个门户**。

> 注意区分:名字像"沃/wo"的 SSID 有两种可能 —— 只是借了个名字的**天翼**网络(门户还是 `enet.10000.gd.cn`),或者真是**联通**自己的认证平台。跑一次 `-DetectPortal` 看跳转地址就知道了,后者目前没有现成预设,把地址发出来就能照着加一套。

### 移动 / 联通 / 电信:运营商不是认证系统

这一点最容易误会,先说清楚:

> **电信、移动、联通只负责出口线路;宿舍楼里那套"连上就弹认证页"的系统,是学校另外采购的。**

所以不存在"移动版认证""联通版认证"——同一所学校,学生接电信还是移动宽带,弹出来的**很可能是同一个门户**;反过来,两所都用电信的学校,门户可能一个是 Dr.COM、一个是深澜。

现实中常见的组合:

| 学校买的认证系统 | 门户特征 | 本脚本 |
| --- | --- | --- |
| **Dr.COM**(城市热点) | `1.1.1.4`、`ac_portal/login.php`、RC4 | ✅ 实测 |
| **广东电信 天翼校园网** | `enet.10000.gd.cn:10001`、`wlanuserip=` | ✅ 假服务器验证 |
| **深澜 Srun** | `srun_portal`、`get_challenge`、`/cgi-bin/srun_portal` | 🔧 骨架 |
| **锐捷 ePortal(RG)** | `eportal/portal/login`、`wlan_user_ip` | 🔧 骨架 |
| **深信服 Sangfor** | `sangfor`、`ac_logout` | ❌ 只认得出 |
| **H3C / 华为** | `portal.cgi`、`hwportal` | ❌ 只认得出 |
| **移动 / 联通自有平台** | `CMCC-EDU`、`wo`、`10086/10010` 域名 | ❌ 只认得出 |

至于**运营商线索**(`-DetectPortal` 会打出来):`CMCC` / `10086` / `和校园` → 移动;`unicom` / `10010` / `wo` → 联通;`esurfing` / `189.cn` / `ChinaNet` → 电信。它只说明"这条线路是谁的",不决定用哪个预设。

**账号形态也跟着学校走**:用 Dr.COM/深澜的学校常常直接填**手机号 + 服务密码**;天翼那套填**学号/手机号 + 校园网密码**。填错了报的是"密码错误",别误判成协议不对。

### 天翼校园网(广东电信)

`esurfing` 预设走的是**天翼客户端协议**,不是网页表单。四个请求,全部 JSON,每个都带 `timestamp` 和大写 MD5 签名(密钥固定串 `Eshore!@#`):

| 步骤 | 请求 | 签名用的串 |
| --- | --- | --- |
| 1 学校 ID | `POST /client/queryschool` | `clientip+nasip+mac+timestamp+secret` |
| 2 会话 Cookie | `GET /advertisement.do?<schoolid>` | — |
| 3 取 challenge | `POST /client/vchallenge` | `version+clientip+nasip+mac+timestamp+secret` |
| 4 登录 | `POST /client/login` | `clientip+nasip+mac+timestamp+challenge+secret` |

两个关键点:

- **不需要识别验证码**。网页版(`qs/index_gz.jsp` + `image_code.jsp`)那套是给人敲的 4 位图形码;客户端协议的 `challenge` 是服务端下发的,原样回填进签名和请求体就行 —— 这也是它能全自动的原因。
- **`clientip` / `nasip` 不用手填**。未认证时跳转地址形如 `http://enet.10000.gd.cn:10001/?wlanuserip=100.2.49.240&wlanacip=119.146.175.80`,脚本从里面抠。MAC 按 `clientip` 反查网卡;如果这个 IP 不是本机的(前面还有路由器 / 经过 NAT),退回用默认路由出口网卡的 MAC。

先用这个看现场(输出里不含密码):

```powershell
.\Connect-CampusNet.ps1 -Mode portal -PortalId esurfing
.\Connect-CampusNet.ps1 -Mode portal -DetectPortal
```

正常会看到 `clientip` / `nasip` / `mac` / `queryschool` / `vchallenge` 五行,`rescode` 是 `0` 就说明协议对上了,接着 `-Mode login` 即可。返回码对照:

| rescode | 含义 |
| --- | --- |
| `0` | 成功 |
| `13002000` | 已经在线(重复登录) |
| `13012000` / `13004000` | 密码错 / 账号认证失败 |
| `11064000` | 登录太频繁,等几分钟 |
| `13018000` | 服务器禁止第三方认证(只能用官方客户端) |
| `13016000` | 账号没订购校园网产品 |
| `11063000` / `13005000` | challenge 对不上 / 超时 —— 脚本会自动重拿 challenge 重试 |
| `13000000` | 签名或参数被拒(多半是 MAC / clientip / nasip 对不上) |

参数都在 `portal.json` 里,可改: `version`(客户端版本号,默认 `214`)、`iswifi`(默认 `4060`)、`macFormat`(`colon-lower` / `colon-upper` / `plain-lower` / `plain-upper`)、`schoolid`(查到后填上可省一步)。

**验证方式**:除了本机真实门户(Dr.COM 全流程登录成功),还起了一个**本地假门户**(监听 127.0.0.1,返回 JSON),分别用 `none` / `md5` / `base64` 三种加密跑通;`rc4_ms` 发给假门户时按预期被拒(它不认识 RC4),说明加密分支和失败判定都对。

天翼这条链路用**假服务器**验证过:mock 服务端独立按协议重算 MD5 签名,四步全部 `sign=True`,`client/login` 回 `rescode 0`,脚本判定登录成功;自动识别也测了(把探测地址指向一个返回假 302 的本地服务,脚本正确把配置从 `drcom` 切成 `esurfing`)。**还没在真实的工贸/天翼网络里跑过** —— 需要在那个网络里跑一次 `-DetectPortal` 才能确认 `version` / `iswifi` / MAC 格式这几个参数对不对。

新引擎的两条路径也都用假门户验过:

| 用例 | 服务端怎么验的 | 结果 |
| --- | --- | --- |
| token 两步 + md5 表单 | 先 `GET /tokenpage` 拿 token,登录必须带 `token=ABC123` 且 `password` 等于 `md5(test123)` | ✅ 三处全对,判定成功 |
| JSON 体 | `Content-Type: application/json`,body 必须是合法 JSON 且 `password` 为 32 位 md5 | ✅ 解析通过,判定成功 |

**`srun2` / `ruijie` 是骨架,不是"能用"**:token 那一步的形状(先 GET 拿 token、再拼进登录参数)是照真实门户的结构搭的,但各校的密码算法(`hmd5(md5(pwd)+token)`、`chksum` 拼法)和参数名不一样,必须按你学校的抓包改两三个字段。谁把这两家真跑通了,欢迎直接提 PR 或把抓包发出来。

**做不到的部分(先说清楚)**

- 带**图形验证码 / 短信验证码 / 滑块**的门户:需要识别验证码,不在本脚本能力范围(天翼走的是客户端协议,没有图形码;但如果你们学校只开了网页认证入口,那套 4 位图形码脚本不处理)
- **Portal 协议加密**(如锐捷的 `wlan_user_ip` + JS 混淆、深澜的 hmd5 带 token):`encrypt` 只能覆盖常见几种,复杂的还得按你学校改模板或加算法分支
- **802.1X / 客户端认证**(锐捷、华为的 supplicant,以及很多学校**教学区**用的 PEAP 企业级 WiFi):那是完全不同的协议,不是 HTTP 表单。像广东工贸教学区的 `GDGM-T` / `GDGM-S` 就是 802.1X,Windows 自己就能连(输工号/学号 + 密码),脚本不掺和;脚本负责的是宿舍区那种**连上要弹认证页**的(`young`、360 之类)
- **服务器明令禁止第三方认证**(天翼 `rescode 13018000`):协议对也没用,只能改用官方客户端

## 已知限制(重要)

**`Stop-ScheduledTask` 不会连带杀掉子进程。** 因为任务动作是 `wscript` → 它再隐藏启动 PowerShell,结束任务时 wscript 被杀了,但它拉起的托盘和守护会留下来。

→ **要停就请用菜单 `9` / `-Mode uninstall`**,它会先收托盘、再收守护(顺序很关键,先收托盘否则它的定时器会把守护又拉起来)。

网速与 WiFi 列表这两个新功能的取舍:

- **网速只统计 IPv4**。IPv6 流量不计入(校园网主要走 IPv4,影响很小);另外是把所有"已启用且非回环/非隧道"的网卡加在一起算,虚拟网卡空转不产生流量,所以不影响读数
- **网速是"此刻速度",不是历史统计**。想在掉线时看当时的网速,只能翻托盘(峰值和累计只在托盘进程存活期间累计,重启托盘会归零)
- **WiFi 刷新要花时间**:每次强制刷新会跑 2 条 `netsh`(约 0.2~0.5 秒)。所以只在"该连的时候"才强制刷新,平时看菜单用的是 40 秒缓存 —— 不会一直刷
- **自动补配置只对开放网络生效**。带密码的网络脚本不去猜密码,配置丢了还是得手动连一次

通知 / 唤醒 / 自动修复这三个的取舍:

- **通知能不能"弹横幅"由 Windows 说了算**。应用只负责把 Toast 交给通知中心(实测已被收下),横幅是否弹出取决于 设置 > 通知 的总开关、本应用的开关、以及"勿扰/专注助手"。被拦了也仍能在 `Win+N` 里看到。想确认就直接 `-Mode notify`
- **会多一个开始菜单快捷方式**「校园网自动登录」。这是通知身份(AppUserModelID)的载体,删了通知就退回气泡模式(功能不受影响)
- **唤醒检测有一点点延迟**。托盘在的话是秒级;托盘没跑时靠守护的"睡过头"判断,最多等一个检测间隔(30 秒)
- **自动修复不动需要重启的动作**。不做 `netsh winsock reset` / `netsh int ip reset`(那俩必须重启才生效),也不改注册表网络栈
- **重置网卡会断十几秒**。所以自动模式下它是最后一招,且 30 分钟内只做一次;不想要这一招就用 `-NoRepair`,或让助手任务不存在(不用管理员安装)
- **修复有节流**:自动修复 5 分钟内只跑一次;手动 `-Mode repair` 不受限制

桌宠这几个坑先说清楚:

- **缩放屏要注意**:脚本启动时会声明 DPI 感知(PER_MONITOR_AWARE_V2)。不这么做的话,125% 缩放下宠物会被系统放大 1.25 倍并且整体偏移到屏幕外 —— 这个坑已经踩过并修好了
- **它是"置顶"窗口**:会盖在大多数窗口上面;和别的桌宠(比如 DSH 里的那只)抢同一个角落时,谁后显示谁在上面,把宠物拖开就行
- **角色不透明的部分会挡住鼠标**:透明区域是穿透的,但点在角色身上会被它吃掉(这是点击挥手/拖动的前提)
- **素材 46.7 MB**:原始分辨率 + 24fps,比按 200px 导出大一倍多;嫌占地方就删掉 `pet/`(宠物自动跳过),或把「大小」调到 60~80%(帧会按目标尺寸解码,内存也跟着降):为了不依赖 ffmpeg/视频解码,帧是提前按 24fps 解好的,所以 `pet/` 目录占地方;删了它宠物就自动跳过(不会报错)
- **动作目前 10 个**(原项目有 106 个)。想加:**webm 丢一起,`python tools/build-pet.py <webm目录> pet` 重转**,右键菜单会自动多出新动作(菜单是按 `pet.json` 生成的,不用改脚本)
- **和别的桌宠抢位置**:都是置顶窗口,谁后显示谁在上;把宠物拖开就行。默认停左下角,就是为了避开常见的右下角
- **帧率受托盘自身影响**:托盘每 2 秒刷新网速/状态的那一拍会顶掉一帧,所以托盘里实测 **23.4 fps**,单独 `-Mode pet` 跑能到 **24.0**;视觉上看不出来。想再高只能插帧(会糊),没做

## 工作原理(门户改版后照这个维护)

```
POST http://1.1.1.4/ac_portal/login.php
Content-Type: application/x-www-form-urlencoded

opr=pwdLogin
userName=<账号>
pwd=<RC4 hex>
auth_tag=<当前毫秒时间戳>
rememberPwd=0
```

- RC4 密钥就是 `auth_tag` 的十进制字符串,输出**小写 hex**(每字节两位,不足补 0)
- 门户还有 3 秒心跳和 `/out.htm` 注销;脚本登录完就撒手,不需要心跳
- 页面里的 `tripledes.js` 当前没被用到(密码登录走 RC4)

## 排错

| 现象 | 处理 |
| --- | --- |
| `用户名或密码错误` | 账号密码不对。学校提示:账号是**新办的电信手机号**,初始密码可能是 `111111` |

| 门户改版全挂 | 看 `reference/` 里的原始 JS,重新核对 `g_url` 与 `onPwdLogin` 参数;若换成 3DES 需重写加密部分 |
| 想彻底删干净 | `-Mode uninstall` → 再删 `accounts.json`、`campus-net.log`、`state.json` |
| 窗口看起来是"老式的" | 先看**有没有标签页**:有标签页就是 Windows Terminal(它托管控台时也会显示为自己的标签页)。本机实测委托是正常的 —— 用资源管理器启动 bat 后会新出现 `OpenConsole.exe` + `WindowsTerminal.exe`,`conhost` 数量不变。另外 `connect.bat` 还会显式调用 `wt.exe`,双重保证。若确实没有标签页,截个窗口图发我 |

## 关于"还没登录 Windows 就联网"

现在任务用"当前用户登录时"触发 + 普通权限。原因:凭据是当前用户级 DPAPI,系统账户解不开。
真要在登录前联网,需要改成 SYSTEM 运行 + `-MachineScope` 机器级加密 —— 需要就说一声。

## 远程适配(朋友不在现场怎么办)

给人远程装这套东西,最缺的不是网络,是**"你那边到底弹的是哪个门户"**。所以有个采集模式,把判断需要的信息一次性收齐。

### 让朋友做这三步

1. 把整个文件夹发给他(或者只发 `Connect-CampusNet.ps1` + `collect.bat` 两个文件)
2. **连上校园网后、还没在浏览器里登录之前**,双击 `collect.bat`
3. 约 20 秒后,屏幕上出现一份报告,**文字已经自动在剪贴板里** —— 让他直接粘贴到聊天窗口发你;同目录如果多出 `collect-日期.zip`,一起发

菜单里也可以:`-Mode menu` → `C) 采集诊断包`。

> ⚠️ **顺序很重要**:一定要在"认证页还活着"的时候采。一旦他自己在浏览器里点过了登录,门户就不再劫持了,采集基本是空的。
> 采集包**不含账号密码**(只有网络、探测结果、门户页面和它的 JS),可以放心转发。

### 采集包里有什么

| 段 | 内容 | 拿来干嘛 |
| --- | --- | --- |
| 无线 | 当前 SSID、状态、脚本目标 SSID、可见网络 | 判断是不是目标网络没设对 |
| 地址 | 本机 IP、网关、DNS、代理环境变量 | 判断网段、是否被代理干扰 |
| 探测 | 联网判定、HTTP 302 门户地址、网关 80/8080、**HTTPS 劫持页标题 + 域名** | 定位门户到底在哪 |
| 识别 | 指纹结果 + 运营商线索 | 决定套哪个预设 |
| 门户页 | 门户 HTML(`portal-1.html`)+ 同站 JS 最多 8 个 | **登录逻辑和加密就写在这些 JS 里**,照它就能写出预设 |

拿到 zip 之后,`portal-*.html` 里能看到表单字段名,`script-*.js` 里能搜到 `encrypt`、`md5`、`password` 这类关键字——当初 Dr.COM 那套 RC4 就是这么逆出来的。

### 更精确的一招(会一点电脑的话)

浏览器弹出认证页 → `F12` → `Network` → 在页面里输入账号密码点登录 → 找到那个 POST 请求 → 右键 → **Copy as cURL** → 粘贴发过来。

这一条信息量最大:URL、表单字段、密码是明文还是密文、有没有加密参数,全在里面。有它就不用猜了。

### 实在要动手点

Windows 自带 **快速助手**(`Win+Ctrl+Q`,或搜「快速助手」),让对方在设置里开"允许协助"给他一串代码就行,不用装第三方软件。
